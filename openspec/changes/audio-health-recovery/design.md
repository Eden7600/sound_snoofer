## Scope and evidence
The Remote API documents Command.Restart as an audio-engine restart and exposes device sample-rate readbacks and level meters. These are useful observations, not a documented end-to-end device-health guarantee. Reference: [VB-Audio Remote API, commands and physical device parameters](https://download.vb-audio.com/Download_CABLE/VoicemeeterRemoteAPI.pdf). [VB-Audio's restart guidance](https://voicemeeter.com/quick-tips-restart-the-audio-engine/) identifies engine restart as a remedy for device/audio problems.

No general stall detection is claimed yet. A feasibility task must reproduce the user's failure and establish which readings change. In particular, sample rate zero/error needs validation per supported backend/version before it can authorize automatic recovery. Some failures may leave positive sample rates, working meters and responsive API calls; those remain manual recovery cases. A constant or zero level, an unchanged parameter-dirty flag, and a silent Element return are never sufficient evidence. Normal silence, gate effects, mute and paused playback must not trigger restarts. No injected test tones, audio recording or extra device capture streams for health probes.

## Health model
Keep endpoint presence, assignment correctness, API connectivity and stream-health evidence separate. States: Unknown, No fault observed, Suspected fault, Recovery queued, Recovering, Verifying, Cooldown, Attention required. Include affected target, evidence timestamp and a concise reason. No fault observed does not mean audible audio was verified.

Poll validated cheap observations on the existing worker at a 500 ms health cadence; do not add full device enumeration to each fast settings edit. An auto-recoverable incident requires a connected, uniquely identified, managed and expected-active device with a validated fault signature for three consecutive samples spanning at least one second. Unknown/failed observations do not count as affirmative stream-fault samples. If the API is disconnected, use existing bounded connection recovery; do not repeatedly send engine commands into an unavailable API.

Suppress fault counting for five seconds after startup, resume, device assignment or engine recovery, and while an assignment transaction is pending. Reset evidence when target identity/generation changes. Normal missing endpoints use ordinary fallback and debounce rather than restarting the engine. SteamVR-ineligible devices, Source Off/unassigned strips, virtual strips without hardware streams and ASIO-patched inputs without independent devices are excluded. A1 remains relevant even when the mic is Off because it can supply the engine clock.

## Recovery policy
Auto-recover audio is a persisted toggle, initially Off. Enabling it permits only experimentally validated signatures; unsupported observations show monitoring limitations and do not silently enable heuristics.

For an eligible incident, recheck identity, signature and recorder state immediately before issuing one standalone Command.Restart = 1 through the existing single live audio owner. Do not combine it with routing writes. Do not clear/reselect devices as a speculative first step, toggle sources, release Volt A1, change sample rate/buffer configuration, reset the mixer or restart any process.

Automatic restart is deferred while recording, paused recording, tape playback or transport state is unknown. Display the reason; when transport is stopped, reevaluate the incident rather than execute a stale request. Manual restart is an explicit disruptive action: normally one activation; when transport is active or unknown, show an in-app confirmation that audio and recording may be interrupted. This is a product interaction, not a requirement to ask for implementation approval. Never automatically stop, resume, replay or start transport.

Only one recovery may be in flight. Apply a global sixty-second cooldown and at most two automatic attempts per ten minutes, persisting attempt timestamps so app relaunch cannot reset a restart storm. A backwards wall-clock change suspends automatic recovery until a trustworthy window is established. An ambiguous command outcome consumes an attempt and moves to Attention required; it is never retried automatically for that incident. Explicit user Retry may start a fresh manual attempt when no operation is in flight. A definitively accepted restart followed by a still-validated fault may get one further automatic attempt after cooldown, within budget.

## Verification and reconciliation
Pause normal native mutations while restarting, retain latest saved setting edits without blocking the UI, and reject concurrent recorder transport commands with a recovery reason. After restart, obtain fresh observations and reconcile the latest managed desired state using the existing safe planner; never restore a stale full mixer snapshot. Preserve saved mic/playback choices, native mute ownership, Volt patches, unrelated sends and unowned mixer settings. Reapply owned mute before enabling any new path; do not clear a user's mute to test sound.

Allow up to ten seconds for responsive API observations and the validated fault signature to clear. Two fresh valid health samples plus verified required managed state establish operational recovery, not proof of audibility. If that evidence is unavailable, report Recovery unverified or Attention required, not success based on the setter returning. Observe recorder state anew without changing it. Element may need separate attention after an engine restart; process presence alone does not establish host ASIO readiness.

Go cancellation cannot interrupt an arbitrary blocked DLL call. A watchdog may mark the actor stalled while leaving UI responsive, but must never issue concurrent DLL calls, abandon ownership or spawn a second writer. Forced termination/relaunch and moving native access into a helper process are outside this change; specify another OpenSpec change if the reproduced failure requires that architecture. This version reports a stuck native call as manual attention.

## Presentation and integration
Controls adds Auto-recover audio and Restart audio engine in the actions area, with concise health/recovery state. Tray exposes Restart audio engine using the same guards. The Stream Deck supported action registry can optionally bind it; no default key assignment needs changing. Shared actions carry client identity and reject duplicate/in-flight requests. Yellow marks suspected/pending/recovery; red marks unresolved failure, with text alternatives. Graph shows unknown or recovering observations honestly; no new Events or Devices tab. A small bounded diagnostic incident record may retain timestamps, evidence and outcome for troubleshooting, never audio content.

Dry-run may observe and preview recovery eligibility but cannot restart, reassign devices or change transport. Existing configs migrate with auto recovery Off. Initial deployment should ship manual recovery and observation even if reliable automatic signatures cannot be established.

## Confirmed failure and remaining acceptance
The user confirms that a device fault stalls audio across all of Voicemeeter and Restart Audio Engine resolves it. Clock failure is a suspected cause, not established diagnosis. Model simultaneous target symptoms as one engine-level incident with one recovery budget and one restart, not separate per-device recoveries. Inspect A1 clock-device evidence first where available, without assuming A1 is always the cause. Reproduce the global stall and establish observable evidence before promising automatic detection coverage. Determine separately whether Remote API calls remain responsive during this audio stall; stopped audio does not by itself mean a hung DLL call. Engine restart interrupts all engine audio, even for a single affected device; acceptance must check Element, active recording and device reconnection separately.

## Implementation status and capability gate
The current adapter has no validated whole-engine stall signature. This build ships manual restart and read-only A1 stream observation. Auto-recover is retained as a preference but explicitly displayed as unavailable; it cannot submit an automatic restart. The automatic budget/evidence gate is unit-tested, but repeated-sample qualification and automatic dispatch are not enabled until a reproducible signature is established. Manual restart verifies API/clock observation only and says audio continuity is unverified. No audio-content analysis or test tone is used. Manual attempts are also journaled, with a separate abuse bound of 64 requests per ten minutes.
