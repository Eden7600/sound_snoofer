# SteelSeries A1 stall — 2026-10-06

## Conditions
The user reported audio stalled with `Speakers (3- SteelSeries Arena 9)` assigned to A1; the Volt was not present. Snoofer was running live with Auto-recover off, so its callback monitor was not registered. Health showed "No engine fault observed (stall detection unverified)".

## Evidence (standalone callback probe, pass-through only, no setters)
| Capture | State | Observation |
| --- | --- | --- |
| `.local/stall-probe/callback-20261006-092801-732.log` | Stalled | Login/register/start succeeded; 0 buffers in 10.157 s (starting=1, no changes/invalid). |
| `.local/stall-probe/callback-20261006-093313-170.log` | After the user restarted the audio engine | 470 buffers by 5.0 s, 939 by 10.0 s, all synchronized; 48,000 Hz, 512 frames, 64 channels. |

## Conclusion
The callback-delivery signature from the Volt incident holds for a WDM device on A1: callbacks stop while stalled and resume after an engine restart. Detection must target the A1 device generally and must monitor independently of Auto-recover.

## Fix validation (2026-10-06)
- **Detection fix:**
  - the monitor registers whenever Snoofer is live;
  - the target is the A1 device: ASIO keeps its presence evidence, and other devices need an available non-ASIO output endpoint with the assigned name;
  - a qualified stall sets `Stalled`, with health "Audio engine stalled: no callback buffers" (plus "restart required" without Auto-recover);
  - the Voicemeeter and callback-monitor cards show Attention, and the GUI header badge is critical.
- **Tests:** unit and worker tests cover a WDM A1 stall, an absent WDM device, an ASIO entry that is not presence, no A1 assignment, an absent installed Volt driver, WDM without a Studio configuration, and alert-only stall reporting with no restart dispatched. The GUI check exercises Restart audio engine on Diagnostics.
- **Checks:** `go vet`, `go test ./...`, the GUI checks and the native desktop check passed. The canonical build passed and Snoofer was relaunched.
- **Live:** with Auto-recover still off, the running build reported "Audio processing active; audible output unverified" for the SteelSeries A1, so the monitor is registered and buffers are advancing (previously "stall detection unverified").
- **Configuration:** the user requested Auto-recover on, and it was enabled through the GUI toggle; the saved state shows `auto_recover: true`. Health remained active afterwards.
- **Not yet verified:** the next real stall being detected and automatically restarted on this hardware.
