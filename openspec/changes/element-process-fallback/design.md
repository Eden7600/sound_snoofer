## Design
Add Element process status to Snapshot (known/running/error). Windows Toolhelp enumerates executable basenames case-insensitively, exact element.exe, accepting any matching process. Missing observation or enumeration failure means unavailable; failure remains visible but does not disable direct routing. Read on each full and parameter snapshot with no subprocess or polling goroutine. Existing serialized worker cadence detects idle process changes on the normal poll; mid-transition snapshots revalidate process state.
Derive effective intent from a clone of the saved intent. If requested mode is Element and Element is not observed running, effective mode is Direct, effective Post monitor is Pre, recording Post is Pre, and ToVST is false. Keep tape ownership so rehearsal sends are cleared. Never persist this fallback: requested source/mode/monitor/capture/rehearsal/loop stay unchanged and resume on host return. Source Off still disconnects mic/return/tape sends; computer playback is unaffected. Explicit Direct continues existing normalization. Process presence does not establish ASIO readiness or plugin health.
This explicitly supersedes the earlier manual-only Direct recovery policy. Post-to-Pre fallback is visibly identified, including capture status, rather than silently substituting dry capture. VoiceStatus includes requested/effective mode and a fallback reason; TUI Processing row shows Element -> Direct and dependent Post/rehearsal rows show effective fallback even at narrow widths. Routing/status views explain unknown vs closed host. Keep Element selectable as a preference while absent.
Use the same effective intent for voice, recording, rehearsal routing, Record guards and recorder protection. Play Snippet requires observed Element availability and verified rehearsal routing. Do not stop/start native tape automatically on process changes; detach its send while unavailable. Returning process may restore selected tape routing, but issues no play command.
Include known/running Element availability in transaction observation key (not changing error wording) so host transitions during application abort and replan. No inventory re-enumeration is needed to check host presence. Unit fixtures explicitly report Element running where required; absence/unknown must never default to running.
