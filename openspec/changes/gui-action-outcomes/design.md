# Design

## Existing flow and scope
`host.ts.send` sets one global pending flag and awaits a binding that returns as soon as it puts
an action in a sixteen-slot queue. The tray later calls the registry; provider handlers enqueue
again. The registry checks the published control revision, but the audio worker independently
checks its shared revision. Other workers can resolve a focus alias or scene slot after its
meaning changed. The frontend currently clears pending on any notice change, a control revision
change or 2.5 seconds, none of which proves a result.

Keep the registry's captured `Request.Revision`, operation/options/availability checks and
bounded handler contract. Handlers still perform no file/device I/O under its lock. Keep the
versioned presentation protocol, unchanged/null polls, artwork caching and connection recovery.
No result is carried in `ViewState`, provider `Control` or the newest-state queue. The worker's
former per-origin `Acks` map could not substitute: it retained only the newest result per origin
and its sixteen-origin limit was unsuitable for arbitrary GUI action identities. The user-directed
`audit-completion` removes that unused worker protocol without changing GUI result identities.

## One result per action, scoped to a child session
Extend private `UIAction` with a string action ID, generated once by the browser and not reused
within that browser session. Keep control ID/revision/operation/value/delta as captured input.
String IDs avoid JavaScript integer precision concerns. The host never treats an ID as permission
to retry a command. Browser attempts rejected before sending also receive local feedback.

`Desktop.Send` returns a typed result for that exact ID. Result meanings are:

| Result | Established fact | What it does not establish |
| --- | --- | --- |
| Submitted | The identified request was accepted for the documented untracked or coalesced work | A save, device write or observed effect completed |
| Processed | The documented save, worker operation or native/RPC call finished without a reported error | The requested native state is observed, unless separately shown by existing readback |
| Rejected | Validation/busy/availability refused this request before its operation began | That a different request failed |
| Failed | This request's processing returned an explicit error; a partial effect may already exist | That nothing happened, or that retrying a one-shot is safe |
| Unknown | Completion/effect cannot be established after timeout, cancellation or connection loss | Either failure or success |

Details identify the operation and concise reason; e.g. Saved, Submitted, Controls busy, Selection
changed, or Outcome unknown. Do not show a generic green Applied/Success badge for Submitted or
Processed. Provider values and Status remain the source of observed/pending/native state.

The desktop owns a map of at most sixteen pending IDs, each with a one-slot result channel.
Reserve a slot before enqueueing to its writer; duplicates among outstanding IDs and exhausted
capacity are explicitly rejected. It never holds its state mutex while waiting for a result, so
State and Animation continue responding. A known local enqueue refusal releases its reservation;
after a possible send, pipe failure resolves Unknown. An unexpected/repeated result cannot settle
another action. GUI IDs are generated by the normal client, not accepted as a general replay API;
the implementation need not retain an unbounded deduplication history after terminal results.

The parent controls session owns a separate reply channel with capacity sixteen. Decoding an
identified action attaches an in-process once-only completion closed over that exact session's
reply lane and cancellation context. It must not look up the mutable current child when replying.
The shared tray action queue rejects a full GUI enqueue explicitly rather than blocking the pipe
reader indefinitely. Legacy internal/tray actions may remain uncorrelated.

One pipe writer selects between the existing coalesced state lane and this reply lane. Result-only
frames have no presentation version or state effect and never pass through `offer`. State floods
must not starve results. Completion never blocks a provider or registry handler. The capacity
invariant is sixteen outstanding desktop reservations, one terminal reply per reservation, and
no reservation release until that reply is consumed or the session ends. Test the saturated lane;
if the invariant is violated, detach that session so outstanding calls become Unknown instead of
silently dropping a reply. Do not add a goroutine per reply or retain a result log.

Closing either pipe, closing the child or host shutdown settles every remaining desktop wait as
Unknown. Late provider callbacks see the old session closed and cannot reach a reopened child.
A stalled provider does not block state polls; the finite reservations contain it. Existing
legacy unversioned native-fixture state still renders and emits revisioned actions; its lack of
a result producer must not prevent EOF/window-close cleanup. Do not modify `check-desktop.cjs`.

## Provider completion contract
Add a small optional, in-process completion facility at the request/dispatch boundary. Ordinary
`Dispatch` callers and its enqueue-error return remain supported. A tracked GUI dispatch supplies
the terminal callback. A provider explicitly claims completion before handing work to its worker;
mere presence of a callback does not mean the provider has promised a later result. Registry or
enqueue errors settle immediately. Successful dispatch without a claim settles Submitted.

A claimed request must finish exactly once on every path: validation rejection, success, explicit
error, queued cancellation, supersession, provider removal/stop and late async completion. The
provider can deliberately finish Submitted after worker validation when the operation enters a
coalescer or untracked external workflow. Keep typed result/control flow separate from Notice or
Status strings; do not parse presentation text to discover success or failure. Audio can adapt a
worker callback without importing GUI types into the worker. Preserve scoped feedback and
origin notice clearing. The original non-GUI Acks retention is superseded by the user's
2026-10-15 `audit-completion` instruction; GUI action IDs remain separate from worker origins.

Every queued command retains the semantic target from the published snapshot, its desired value
when a toggle was resolved there, and the provider context/lifetime needed to validate it. Do not
re-resolve a queued alias against a newer app/player/room/channel or replace its revision with a
new one. Use existing provider generations and stable IDs where they already express the target;
add only the small missing worker-owned generation for a mutable alias/lifetime. Recheck at
dequeue before side effects. Registry revalidation alone is insufficient if worker context has
already changed before its next publication. Reject a disappeared/recreated or changed target;
do not select the nearest/current replacement. Preserve intentional same-target accumulators.

### Bounded provider work in this change
These are completion boundaries, not new readback engines. Claim at most through the already
owned queue/async operation; do not hold GUI slots through indefinite reconciliation.

| Provider/path | Required result boundary and remaining native status |
| --- | --- |
| Audio intent edits | Return worker stale/validation/save errors and Processed after save-before-apply. Native mute/routing disagreement remains existing Pending/Unknown/Failed status. Carry the result through priority/output edit save and the requested worker reload; a successful file save alone does not claim reload succeeded. |
| Audio gain, recorder, recovery | Carry through the current bounded worker/controller operation, preserving gain identity, recorder revision/confirmation and no-replay checks. Report explicit errors. An engine restart merely submitted for recovery is Submitted; do not label it recovered. Existing controller verification/readback remains unchanged. |
| Audio-linked Soundboard volume and Discord mute | Pass an optional completion through the existing audio adapter so delayed audio stale/save/native-call errors reach the originating GUI action. Non-GUI reconciliation may continue without a callback; it gains no relaxed mute generation policy. |
| Stream Deck editor | Keep existing editor revision/context checks, make stale/busy/save refusals explicit and complete after the draft mutation/save path. Capture page/layout/shared/remembered-deck context and never apply an old queued edit to a newer editor target. |
| App Audio | Complete settings edits after save and volume/mute after the finite captured session writes return, including joined partial-write errors. Capture logical app/focus and session membership/lifetime so queued input cannot land on newly grouped/reopened sessions. Pending/readback/ignored status continues separately. |
| Now Playing | Complete settings and focus edits at their worker boundary. Capture session key/source/lifetime for focused aliases and explicit session commands; return invalid/unavailable errors. A Windows media call completes when its bounded call returns; browser commands report Submitted after the socket write, or its write error. Deferred dial seeks report Submitted when accepted into the existing same-target scrub accumulator. Later playback/readback timeout remains native Status. |
| Windows Media | Complete after SendInput returns; partial/failed injection is an explicit error. Never invent observed playback state. |

| Hue accumulated controls | Brightness, group dials and coalesced Sync values report Submitted after worker validation and acceptance into their existing accumulator. For async owners, finish claims even when their normal state-update closure is discarded because
the generation changed or context ended. Unknown is appropriate once a write may have happened;
a worker can reject a queued operation it knows never began. Superseded preparation that never
played can explicitly say Cancelled before playback. Never infer not-applied from a transport
error. Existing desired-state reconciliation, rate limiting and readback continue; this change
adds no GUI-driven retries and does not replay one-shot scene, recorder, media or clip actions.

### Discord toggle-only commands
Discord Camera and Screen Share expose toggle RPCs, not explicit setters. Capture the
connection generation, channel lifetime and published observed state with each command. When
that state is known, retain the desired transition and reject a changed observed state before
issuing the toggle. When it is unknown, retain that unknown state and reject if a newer known
state arrived before dequeue; acceptance promises only the nonce RPC response boundary, never
a desired or observed Camera/Share value. This does not change the existing availability of
unknown-state toggles. Channel departure and return invalidate the old command even when the
same channel ID is reused. No command retries after an uncertain result.

### Now Playing source identities
The current Windows `AppUserModelID` plus enumeration suffix and browser `tab:frame` keys name
display/control slots, not source lifetimes. Keep those IDs and persisted settings unchanged.
The adapter needs the following private identities before it can promise captured-target checks:

- The native media companion adds an opaque string instance token to each snapshot session.
  Reuse a token only for the same canonical COM `IUnknown` identity retained in the last successful
  snapshot; hold the COM/session reference while comparing identities. New or previously absent
  objects receive a fresh counter value. This prevents enumeration reorder and address reuse from
  redirecting a command. Release retained references when a session leaves that snapshot and when
  its handle closes. Keep only the current snapshot, not retired-session history. `MSCommand`
  resolves the instance token; thumbnail lookup can retain the existing snapshot ID. Snapshot
  buffer retries must not replace the committed session table until delivery succeeds. The Go
  worker additionally captures its Windows-source generation so close/reopen invalidates queued
  commands even if a new handle starts its counter over. Missing tokens from an older companion
  make session commands unavailable; never fall back to enumeration IDs.
- The bridge gives each accepted connection a monotonic generation. Reports and disconnects carry
  it internally; the worker accepts reports only for the live connection and removes only the
  matching stored generation. A queued command captures that generation and `send` checks it
  before writing to that exact connection object, never a replacement found by browser name.
  A replacement between this check and the write can fail or reach the old connection only.
- The extension assigns an opaque string instance to each content-port connection. Reports and
  commands include it, and routing checks it against the current frame before any action. An old
  port cannot overwrite its replacement's report, and old WebSocket callbacks cannot act for the
  current socket. This closes navigation/content-port replacement after host validation but before
  extension routing. Connection generation plus frame instance distinguishes a background restart
  even when its local counter resets. A tab-mute write still targets browser-tab state; the token
  check is at extension dispatch, not an atomic guarantee against later browser navigation.

Use the existing protocol-version refusal handshake to move the browser wire format from 1 to 2.
Require bounded nonempty instance strings; incompatible extension/host pairs explicitly request
an update instead of silently using the old command shape. In protocol 2, existing `toggle` and
`mute` commands carry the captured desired boolean as `value` 0 or 1, including explicit zero.
The extension applies that desired value; it does not invert a newer playback/tab state. Windows
toggles likewise resolve to the existing Play/Pause operation before enqueueing. Keep next/previous
and seek one-shot semantics and the existing same-target dial accumulator. The accumulator retains
the captured source/session lifetime and discards obsolete work before its deferred seek.

Session commands also retain the necessary published capabilities/context; focused aliases retain
their focus generation. Settings capture the raw-settings identity and explicit desired value.
Validate before work begins and classify known missing/changed targets as Rejected. A finite
Windows call returns Processed or its explicit error; a browser write returns Submitted, with
ambiguous write errors Unknown. Extension-side refusal after a successful socket write does not
turn Submitted into observed success. Existing pending/readback status reports later uncertainty.
Do not add a browser command-reply protocol, a new identity service or unbounded token history.

Verify native identity reuse/reorder/removal using fake COM objects through the production helper,
and Go/browser lifetime handling with isolated fake sources, loopback sockets and extension tests.
Extend the existing media self-test build path; keep companion packaging and extension acceptance
in the coordinated native checkpoint. No live player is needed for the isolated identity checks.
The native helper and companion must compile under the existing MSVC `/W4 /WX` settings; Go and
extension tests cannot establish that. If that toolchain is unavailable, record the exact blocked
check and leave native validation open rather than install a replacement or claim completion.

## Two independent global mute preferences
Only requests for `audio.mic-mute` and `audio.speaker-mute` receive the independent policy. The
audio worker owns two monotonic generations in its immutable State. Publish the corresponding
generation as each explicit control's Epoch; every other audio control keeps the overall worker
revision. Registry publication/Request.Revision validation remains unchanged, including legitimate
availability/value/status changes on those two controls.

The provider resolves each click into its explicit desired boolean and captures that preference's
generation in the internal Action. The worker may accept it after an unrelated overall revision
change only when the exact preference generation and intent lifetime still match. It edits the
current configuration, so a prior accepted change to the other preference is retained. Save using
the current worker-owned StateToken through the unchanged SaveIntent compare-and-swap; native
application follows the existing save-before-apply path.

Advance a preference's generation whenever that preference changes, including changes made by
other callers. Invalidate both at an accepted reload/reset boundary and whenever
the intent becomes unavailable or is replaced, even if its boolean values are equal. Keep counters
monotonic for the worker lifetime. Do not use boolean equality alone: false→true→false must still
invalidate an old queued request. Recreated providers cannot process old-lifetime queued work.
An external saved-choice edit still fails StateToken CAS; no generation exception bypasses it.

This is not permission for arbitrary edits to commute. Profile selection, routing, recording,
gain physical identities, restart confirmations, mic stack and reset retain their
strict overall revision/target guards. Gain-press aliases and Discord's linked-mute reconciliation
also retain their existing strict policy; only the two named explicit controls opt in. Global
mute preferences remain global across Normal/VR, so a profile transition does not select a new
hardware action target. Native observation never overwrites either saved preference.

## Frontend attribution and busy state
Replace global pending with a bounded map of outstanding actions keyed by action ID. Capture the
origin screen, control label/ID, busy key, request revision/target and creation/deadline before
awaiting Send. Ordinary controls use their semantic control ID as the busy key; existing mirrors
share that key where they affect the same operation. Lifecycle actions share one lifecycle key.
Do not invent whole-screen/provider locks to hide stale errors. Different controls can send
concurrently; another attempt for a busy key is visibly refused rather than silently discarded.
The two global mute controls have separate keys.

Disable/mark busy only the affected widgets or explicit lifecycle group. Remove all global
`!!appState.pending` gates in screen builders; audit command, mixer, seek, scene, routing, plugin
and editor controls as well as shared widgets. Keep navigation, telemetry and unrelated editing
available. Preserve focused-input/dropdown deferral and local confirmation snapshots; an unrelated
pending action must not force a focused editor to rebuild. State preservation is otherwise owned
by its existing change.

While waiting show Sending beside that control (and a compact transient aggregate in the header
if needed). At the existing 2.5-second display deadline show Outcome unknown; still waiting.
Keep the Promise and busy reservation until an actual terminal result or disconnection. A later
result replaces only that action's provisional Unknown. Neither a revision/Notice/Confirmation
change nor a no-change poll clears its pending state. Local poll updates must continue timing it.
Never resend after timeout, refusal, result error, navigation or connection recovery.

Store only outstanding actions plus the latest feedback per existing control and a bounded
per-screen summary for a vanished target/lifecycle action. Do not build a history. Retain unresolved
screen-local errors when navigating away and show them on return; completion from the old screen
must not flash an error on the current screen. A newer action on that same control supersedes its
old displayed feedback, but cannot delete another outstanding action. Dismiss affects only the
displayed local feedback. Reconnection clears only the global banner. Correlated GUI dispatch
errors stop writing the shared host Notice; unrelated host diagnostics retain their meaning.

## Identity-safe lifecycle proposals and confirmations
Publish the current configuration revision alongside enablement so a selection action captures
the version it was drawn from. Reload/validate at selection handling and reject a changed config;
do not silently rebase a selection onto a newly enabled dependency set. Construct one proposal
record containing a fresh ID, owner controls session, source action ID, expected configuration
revision, proposed config and the captured confirmation text. Reject another selection/retry in
that lifecycle group while a proposal is active instead of overwriting it.

Publish the proposal ID with its text. Confirm and Cancel carry that exact ID; check both owner
session and ID, consume once, and refuse an old/duplicate/missing ID. A stale Cancel cannot cancel
a newer proposal. Confirm retains the existing Save expected-revision check; external edits leave
the saved configuration untouched and return the error to that confirm action. A successful save
can report Saved; restart requested, never that the restarted host is already healthy. Queue its
result before shutdown; if the pipe closes before delivery, the desktop correctly reports Unknown.
Do not block shutdown indefinitely waiting for result delivery. Closing the owner GUI abandons
its unconfirmed proposal and releases the lifecycle group.

Local confirmations from `gui-state-preservation` still freeze request ID/control revision/value
and target context when opened and send only once after confirmation. Adapt their busy checks and
host proposal identity to this API; do not convert confirmation into a fresh `press(id)` lookup.
Cancelling a local confirmation sends no action. Polling continues during either kind of dialog.

## Verification and checkpoints
Use isolated fake workers/backends, temporary configuration/state and controlled browser time.
First add failing tests for the current lost second mute click and misleading/global outcomes.
Land the completion/pipe contract with tests, then the independent audio generations and worker
results, then provider adapters in small groups, then frontend attribution and lifecycle identity.
Test every newly claimed queue's stop/cancel paths and every async callback's late-result path.

Coverage must include full desktop/tray/provider queues; out-of-order and duplicate completions;
state flooding without reply loss; sixteen blocked Send calls while State still responds; timeout
without slot release/replay; disconnect/reopen with late old replies; both mute orders, ABA,
reload/reset/lifetime and external StateToken rejection; contextual target changes before dequeue;
delayed save/native errors; coalesced Submitted boundaries; per-screen errors and stale confirmation
IDs. Preserve existing no-replay, physical target, actor shutdown, keyboard and accessibility tests.

Run focused Go tests and frontend gates after each checkpoint, then the full source-only suite.
Check new feedback at 1280×820 and 800×600. Keep isolated checks independent of deployed binaries
and personal configuration. The user has lifted the temporary running-app restriction; the
coordinating agent schedules canonical build/restart, WebView2 and real-device checks after stable
source checkpoints. Keep each unperformed check open. Do not treat source-served browser tests
as native acceptance.

### Live delayed-native-error acceptance
Use the normal Soundboard GUI and production Media Foundation decoder with one disposable,
uniquely named regular `.mp3` containing invalid media. First verify Soundboard is idle and
ready. Create the new file without replacing any existing file in the configured clip folder;
its unique identity must have no normalized cache. Wait for the normal catalogue refresh and
press the clip once. The catalogue checks extension and file metadata, so unchanged input
reaches the asynchronous native normalization path without a test hook or configuration edit.

Count this check only when the originating Soundboard action reports Failed with the actual
Media Foundation normalization HRESULT. A stale/readiness refusal or file/cache I/O error
does not establish native decoder failure. No playback should start. This verifies a native
error returned after enqueue; it need not exceed the GUI timeout and does not verify Unknown,
an uncertain one-shot or no replay. Remove only the exact disposable file afterward and
confirm its catalogue entry disappears. Preserve user media, configuration and current
audio choices throughout; leave the other task 6.3 checks open.
