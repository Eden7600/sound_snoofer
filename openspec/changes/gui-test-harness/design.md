# Design
## Layout
```
app/web/test/
  playwright.config.ts   projects: desktop 1280×820, small 800×600 (layout specs only)
  host.ts                fake Desktop binding and page fixture
  fixtures/
    audio.live.json      generated by plugins/audio golden test
    audio.preview.json
    streamdeck.json      generated by plugins/streamdeck golden test
    manual.ts            hand-written controls (see Fixtures)
    index.ts             fixture builders: base(), with overrides per test
  audio.spec.ts, routing.spec.ts, deck.spec.ts, soundboard.spec.ts, lights.spec.ts,
  appaudio.spec.ts, meetings.spec.ts, media.spec.ts, plugins.spec.ts, diagnostics.spec.ts
  journeys.spec.ts       cross-screen flows (navigation, errors stay local, keyboard)
  a11y.spec.ts           axe-core scan of every screen
  layout.spec.ts         geometry at both viewports
```
Tests are TypeScript. Playwright Test transpiles them; strict type-checking of test code joins the GUI's `tsc` run in `gui-typescript-modules`.

## Serving and host
- No HTTP server. Each page routes `http://snoofer.test/**` to files under `app/web` with `page.route`, so the suite serves exactly what `index.html` references, before and after the TypeScript bundle.
- `host.ts` installs `window.go.app.Desktop` with `State`, `Animation` and `Send`:
  - `State` returns a deep copy of the test's fixture, with meter timestamps refreshed, as `check-gui.cjs` does today.
  - `Send` records actions and applies the same small set of fixture mutations the current script applies (value set, revision bump, deck region edits).
- Each test gets a fresh fixture object, so no state leaks between tests.

## Fixtures
- **Generated:**
  - A Go golden test in `plugins/audio` builds `control.State` values for a fixed studio (live, and preview) and publishes them through `controls`, `slotControls` and `priorityControls` and the real registry. Its configuration is `plugins/audio/testdata/gui-config.json`, which mirrors the hand fixture's scenario (Music output, desk/lav/webcam, an ambiguous Arena match) so the ported specs keep their intent.
  - A test in `plugins/streamdeck` publishes the editor view and binding controls for a fixed layout.
  - Both marshal to JSON and compare with the committed file. With `SNOOFER_UPDATE_FIXTURES=1` they write it instead.
  - Timestamps and meters are fixed values; the browser host refreshes meter times.
- **Hand-written** (`manual.ts`): Soundboard, Hue, App Audio, Now Playing, Discord, AEC, VR, plugin states and notices. Each block names why it is not generated yet: its controls come from a worker with network or OS backends and no fixed-input entry point. Generating them is follow-up work, recorded in `docs/gui-audit.md`.
- **Porting:** the port step keeps today's hand fixture verbatim, so behavior is compared like for like. Generated fixtures replace the audio and deck parts afterwards. Where they expose known defects (raw Processing/Monitor values, "virtual:1 Playback"), the tests assert today's output, marked with `gui-content-fixes` as the owner, so the fix changes the expectation in the same commit.

## Accessibility and keyboard
- `a11y.spec.ts` runs axe-core (WCAG 2.1 A/AA rules) on every screen.
- Violations that exist when the suite lands are listed in `known-a11y.ts` by rule and target, each with an owning change. The test fails on any violation not listed, and on a listed entry that no longer occurs, so the list only shrinks.
- Keyboard journeys cover sidebar navigation (arrows, Home, End), deck grid movement and range selection without dispatch, dialog confirm/cancel by keyboard, and text fields that apply only on Enter/Apply.

## Layout checks
For every screen at both viewports:
- no horizontal page scroll;
- every visible button, input and select lies inside the viewport width and is not clipped by an `overflow: hidden` ancestor;
- no two visible interactive elements overlap.

Known layout defects use exact screen, viewport and affected-control expectations, each owned by a follow-up change. The suite rejects both new defects and obsolete expectations. This keeps the test-only migration honest about existing defects, including the narrow Stream Deck save-bar overlap owned by gui-layout-polish. Each test attaches a full-page screenshot on failure, and the layout spec always attaches one per screen for review. There are no committed baselines: fonts and rendering vary between machines, and geometry assertions catch the defects baselines were meant to catch.

## Browser and budget
- `channel: "chrome"`. `globalSetup` checks that the installed Chrome can launch. If it cannot, it fails with "Install Google Chrome; the GUI suite never downloads a browser". `@playwright/test` has no install-time download.
- **Budget:** the whole suite under 60 s with default workers. Today's single script takes about 27 s. The budget is checked in the validation task, and the config sets a 15 s per-test timeout.

## check.ps1
- `scripts/check.ps1` builds the CSS and runs `npx playwright test -c app/web/test`, failing the check on any failure.
- `-GUI` keeps the native WebView2 smoke (`check-desktop.cjs`), which is unchanged.
