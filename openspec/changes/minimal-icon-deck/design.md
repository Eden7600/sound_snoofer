## Design
Group controls by workflow on the nine-column deck. Row 1 has mic mute, playback mute, monitor and processing in positions 1-4, with Open controls at position 9. Row 2 has the recording toggle at 10, a spacer at 11, then mic capture, computer capture and mic stage at 12-14. Empty cells remain reserved. Media occupies zero-based indices 27/28/29, the first three keys of the bottom row, as confirmed by the user. Preserve custom serial profiles and legacy action identifiers for compatibility.

Present current state in plain words: LIVE/MUTED for mic, AUDIBLE/MUTED for output, PRE VST/POST VST for stage/monitor, DIRECT/ELEMENT for processing. Media buttons have no fictitious playback state or PRESS caption. Recording uses the action label RECORD or STOP REC and observed state. Use quiet dark key backgrounds with category accents, recording red and mute red accents. Pending and unavailable states remain readable local status; do not paint the entire key bright red for an unavailable observation. Processing/monitor/stage fallbacks display effective state with amber fallback indication rather than promising a saved preference is currently active.

Resolve record-toggle at queue dispatch from observed recorder state. Stopped submits RecordStart, Recording or recording-paused submits RecordStop. Unknown/disconnected/playing/non-recording paused submits nothing. Reuse revision checks, serial queue and native verification; never infer transport state from saved preferences. Start and stop feedback includes record-toggle. Show record circle when stopped, stop square while recording, and unavailable when the toggle cannot run.

Use dependency-free vector primitives rasterized into existing 112px JPEG keys. Add mic, speaker, monitor/headphones, processing sliders, recording circle/stop, computer, stage and media transport symbols. Keep concise label plus value below icons; blank keys contain neither text nor icon. Native rotation and changed-image upload caching remain unchanged. The record icon changes with observed state and enters the presentation cache key. Retain text fallback for custom bindings without an icon. Rewind/forward use the existing previous/next Windows media commands.

Tests cover exact positions and blank dispatch, queued start/stop using acknowledged state, unavailable recorder states, scoped transport feedback and rendered image geometry. Export and inspect a rendered deck preview; run full tests, vet, strict OpenSpec validation and Windows build. Physical acceptance remains separate.

## Shared mute interaction
The speaker button and a knob targeting the current playback bus must act as aliases for one effective mute preference. At queue dispatch compute the union of playback-following and fixed-bus preferences. Either control toggles that union: write the playback-following preference and clear the overlapping fixed-bus preference atomically. Knobs for other buses keep their independent fixed-bus preference. This prevents hidden ownership from making unmute ineffective and keeps playback mute following device changes. Native preexisting/manual mute ownership safeguards remain intact. The button readback combines both requests, and rendering shows MUTED/ON rather than ambiguous toggle On/Off, with a slashed speaker/mic icon when muted. Test alternating button/knob presses, both flags initially set, and a non-playback bus unaffected.
