## Design
Exactly two tabs: Controls and Graph. Both directions of Tab/arrow navigation cycle between them; leaving a picker cancels it without submitting changes. Controls retains its existing selection and behavior. Graph uses the full content width and vertical scrolling, with no duplicate status sidebar.

Render a deterministic directed adjacency graph using ASCII brackets, branches and arrows. Each observed strip with enabled sends has a source node and outgoing bus edges; hardware buses terminate in their currently assigned device. Include physical input names, observed ASIO L/R patches from A1, VAIO/AUX/VAIO3, native recorder playback sends and armed bus recording paths. Potato's configured voice profile labels B1 recording mix, B2 Element send and B3 application mic. Generic/legacy profiles retain neutral bus names. An external B2 -> Element -> AUX link uses dotted ASCII arrows and explicitly says external path is not verified; process presence cannot establish signal flow. Recorder transport state labels distinguish an armed path from active playback/capture.

Snapshot numbers and assignments are authoritative. Never draw desired-plan or draft-intent edges as applied, including preview, Off pending and output migration. Unknown sends are reported as unknown, not off; disconnected/error snapshots are not drawn as current. Show compact pending/preview and unresolved/fallback notes from the existing plan, without retaining its old operation-list UI. Device labels are sanitized and truncated per node/edge to terminal width. Long routes split across lines on narrow terminals; edge syntax remains legible. No source selection or routing writes from graph navigation.

Remove screen.lines, ruleLines, the inventory-tab test, State.Events and the worker's ring history/log calls. Keep the controller event callback only to maintain active error state; controller events used by CLI watch remain. Keep Snapshot, device inventory helpers and Plan because routing, selectors, status and pending/fallback indicators still depend on them. Update README's current tab/diagnostic guidance, leaving historical OpenSpec records intact.

## Verification
Test direct/Element paths, pre/post monitoring and capture, tape rehearsal, Off, playback bus migration, absent devices/unknown sends, disconnected state, generic Banana topology, sanitized names, two-tab navigation including picker cancellation, resize and scrolling. Full tests, vet, strict OpenSpec validation, Windows GUI build and isolated preview keyboard smoke. No live mixer mutations.

Cleanup also removes presentation metadata with no remaining consumer: duplicated RecorderNotice (use the existing active Notice), unused State.Updated timestamp, and the unused controls configPath field/renderer argument. Since the detached renderer never loads configuration, remove the now-unused configuration-path argument from its private child command and launch helpers too. The tray worker retains its configuration path and persistence behavior.
