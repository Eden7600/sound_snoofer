## Control service
Move only the shared action/state boundary out of TUI ownership into an application control service. Keep the single serialized, OS-thread-affine Voicemeeter writer and existing tray lifetime. TUI and hardware clients submit typed actions with origin/session/sequence identity; acknowledgment is scoped to that client. One client cannot consume another client's result. Publish immutable snapshots through bounded latest-state subscriptions. Reject stale target generations; never reinterpret an old mic-gain command as gain for a newly selected mic.

Persistent settings remain save-before-apply. MicMuted and PlaybackMuted are independent booleans, migrated false, and never rewrite Source or Enabled. Transport stays one-shot, nonpersistent and never replayed on reconnect. Relative gain changes are ordered and coalesced only for the same target/generation; accumulated deltas must not be lost or applied twice. Use a known verified gain plus pending ordered deltas; reconcile manual mixer changes with fresh readback before the next batch. Unknown current gain disables relative adjustment until refreshed.

## Native gain
Add narrowly validated floating-point gain operations and readback for Bus[0].Gain, Bus[1].Gain and the resolved physical mic Strip[n].Gain. The existing integer send/patch setter is not suitable. Validate finite values, use invariant numeric formatting through the existing parameter script ABI, and confirm documented gain limits against the installed Remote API documentation before implementation. Default encoder increment is 1 dB per tick, clamped to verified parameter limits. Report actual dB and target name. No selected physical mic means unavailable. Gain belongs to native mixer state: do not persist every tick or restore stale gain at startup. Refresh observations so manual Voicemeeter gain edits appear on connected surfaces.

## Built-in mute, no source switching
Mic mute uses native Strip[n].Mute on the active physical mic and the managed Element return. This silences direct, pre-monitor/capture and processed voice, including effect tails and rehearsal return. Sends, ASIO patches, hardware assignments, source selection, recording inclusion and recorder transport remain unchanged. It does not unmute or activate Source Off. Rehearsal continues playing silently through the return while mic mute is active; make that visible.

Scope mute ownership to managed voice strips while active; retain observed prior mute state when acquiring a newly managed strip and restore it on release only if the value is still the one Snoofer wrote. Preserve ownership baselines across a recoverable process restart or report uncertain ownership instead of guessing an unmute. Unmute removes Snoofer's mute request; it must not clear a pre-existing manual mute. Present native observed mute separately from the requested state when these differ. Reassert a requested mute if external edits defeat it, using normal bounded verification, never broad routing rewrites.

Playback mute targets native Bus[n].Mute for the effective playback output. Fixed A1/A2 controls remain tied to their named buses; speaker mute follows playback. Apply mute to a new target and verify before routing audio to it, then release the old target with the same ownership discipline. Mic source changes while muted similarly prepare and verify the new strip mute before enabling its sends. Failure keeps the new path from becoming audible and reports pending/failed state. Mute alone never calls device setters or rearranges buses. Independent mic mute must not mute computer playback or capture.

## Responsiveness and UI
Gain/mute use the numeric fast path, aiming to submit eligible changes within 20 ms when the actor is available, with no device debounce or inventory refresh. Verification and contention can take longer; show pending until observed. No promise of 20 ms audible effect. Controls exposes mic and speaker mute; Graph annotates observed mute without deleting routes. Gain state feeds hardware and concise controls, not a new mixer editor. Yellow pending and red unmet/failure markers have textual equivalents.

## Validation boundaries
Test multiple clients, pending deltas, source generation changes, mute baseline ownership, partial failure and disconnect/reconnect using fakes. Real Element tails, native recording and hotplug audibility require separate acceptance. Dry-run makes no audio writes. Confirm exact native parameter domains during implementation before enabling writes.

## Fixed-bus mute composition
Expose explicit A1/A2 mute requests for encoder presses, independent of PlaybackMuted. Effective bus mute is the union of these requests and any preserved native baseline. Clear only the releasing request; transfer playback mute without losing explicit bus mute. Persist explicit bus requests with the other mute preferences.

## Implemented persistence and control boundary
Mute baselines are saved atomically to a private config-adjacent .mutes.json journal before writes; recoverable restarts reload those baselines. Journal errors block mute reconciliation rather than guessing an unmute. The control worker now lives in internal/control; the TUI retains aliases for its existing wire format. The tray fans immutable snapshots to controls and hardware. Hardware acknowledgments have an independent bounded origin map, so a hardware failure cannot overwrite the TUI edit acknowledgment. The implementation additionally rejects stale gain revisions, even if the same physical target has since returned.
