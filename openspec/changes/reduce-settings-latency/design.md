## Audit
TUI actions wake the worker immediately; the 1-second UI tick is presentation only. Source/output choices intentionally perform fresh inventory confirmation before saving. SaveIntent synchronously flushes/replaces the sidecar and remains unchanged for durability. Source Off can clear device assignments and therefore uses device debounce; changing existing mic sends, mode, monitor, capture source/stage, loop and rehearsal normally uses 20 ms unless observed hardware also needs repair. Recording/Play/Stop have no routing debounce but native Record/Stop confirmation currently polls at 100 ms. Inventory discovery remains on the 1-second poll, so physical hotplug detection adds up to a poll period before debounce. Setter failures keep bounded exponential retry; no retry of uncertain recorder transport.
## Design
Lower the default and active device debounce to 1000 ms. Existing explicitly configured values outside shipped examples and the active config remain supported. Numeric debounce remains 20 ms.
Remove the transaction-wide fast/slow switch. Before each changed numeric operation refresh parameters without enumeration, even in mixed transactions. Before each changed device assignment take a full snapshot; inside verification use parameters at 20 ms intervals, and once assignment matches take a full snapshot to confirm inventory, all owned cells, and the assignment before proceeding. Full transaction start/end checks remain. This bounds full enumeration to transaction boundaries plus twice per device assignment, not per routing operation or wait retry. Backends lacking ParameterSnapshot continue using full snapshots. Parameter refresh errors/cancellation/drift abort immediately; inventory changes during a pending setter are detected on its full confirmation before further writes. Never enable destination sends before device confirmation.
Recorder Record/Stop preparation and transport polls use 5 ms capped to remaining verification time, keeping deadline and uncertain-outcome behavior. Do not add goroutines or remove disk durability or fresh eligibility checks.
## Validation
Test deadline at 999/1000 ms, mixed-transaction full/parameter read counts, delayed device confirmation, inventory mutation at confirmation, unrelated-send isolation and recorder timeout/no-retry regression. Full suite, vet, Windows build, strict validation and preview startup. No promise that complete device switches take exactly 1 second: debounce, native device open, full inventory and readback all contribute.
