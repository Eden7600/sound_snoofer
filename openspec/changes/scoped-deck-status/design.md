## Design
Do not use State.Notice or Plan.HasChanges as a blanket key overlay. Global diagnostics remain in the TUI/tray. Add bounded, immutable per-binding action feedback to shared State: Pending for an executing command, Error for its failed result, then clear on retry/success or after ten seconds. Use a notice revision counter to associate errors with the current command rather than inheriting an old global notice. Record stop and snippet stop share their underlying transport result. Gain feedback has separate target keys and must not mark button bindings as failed.

Compute each button's presentation independently. Route settings are pending only if a changed plan operation affects that setting's routes: monitor A sends, processing B2/B3, mic capture B1 for managed microphone/return strips, computer capture B1 for virtual playback strips, rehearsal recorder sends, and loop's own parameter. Native mute compares the relevant observed strip/bus mute parameters, including Element return and fixed-bus requests. Use observed recorder state for transport labels. Unknown audio state is UNAVAIL, not ERROR; media and Open controls remain available independently. Preview remains visibly PREVIEW and must not look successfully applied.

Produce a small pure presentation model containing all key labels/values and knob labels/gain/mute text. Use that model as the rendering cache key and as the only image-renderer input. This ensures parameter changes, per-binding feedback expiry, mute targets and effective mic identity invalidate the right images. Existing encoded-image diffing prevents unchanged keys being uploaded. Tests compare actual JPEG tile bytes so unrelated edits and notices must leave unaffected keys identical.

This fix does not add an overlay for events still queued in the desktop hardware queue; pending begins when the actor processes an action or when the affected routing readback differs. No global pending indicator is inferred from another setting's edit.
