# Design

No args or a leading non-help flag resolves to tui. TUI defaults to live; --dry-run overrides live. Watch also defaults live, retaining explicit --apply compatibility. Devices/plan remain read-only. Keep explicit --config support; only TUI supplies an implicit config path. Resolve it from os.Executable rather than cwd. Missing default config is created exclusively from an embedded copy of the voice/recording example; never overwrite existing defaults, explicit configs or state files. Errors are surfaced normally. Runtime choices use the existing adjacent .state.json mechanism.

For this user's installation, copy config.local.json and its state sidecar to bin/config.json and bin/config.json.state.json before first normal launch, if destination is absent. These remain ignored local data. Ship the rebuilt bin/sound-snoofer.exe. Rename cmd directory, module/imports, labels, lock identity, build commands and maintained docs/spec references. Rename the project root to Documents/sound_snoofer, preserving .git and ignored local assets. Historical git objects and zipped scratch backups remain historical rather than being rewritten. Verify no running legacy executable before retiring the old binary; do not stop user audio processes.

The explicit request supersedes the old default-preview invariant. Keep live writer ownership and recorder transport safety; default startup never starts recording. Test launch through injected executable/TUI dependencies without native writes. Smoke-test the new executable from another cwd with --dry-run. Confirm path, build, tests, config preservation and clean Git status. Live hardware changes are not needed to validate launch defaults.
