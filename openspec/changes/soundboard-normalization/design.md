# Design
Peak normalization is explicitly selected by the user because some clips are intentionally perceived as louder. Preserve those differences and dynamics; do not level perceived loudness or compress. Decode MP3 to native-rate mono/stereo 16-bit PCM using Windows Media Foundation Source Reader. Find the largest absolute sample and apply one constant gain to reach -1 dBFS (29205/32768 after quantization); zero peak remains silence. No compression, limiting, cross-clip loudness measurement or original-file writes. The existing VAIO3 volume dial remains downstream and resets to 0 dB independently.

Extend the existing soundboard companion with a normalization export and link Windows SDK libraries. A cancellation event is checked between decode buffers and before output. Bound decoded PCM to 64 MiB; reject empty/unsupported files and changing sample formats. Native cleanup balances COM/MF and files on all paths.

Prepare lazily on first press in one background job. The playback actor remains responsive; Stop cancels pending preparation, replacement cancels old work and retains only the latest requested clip, and only one job runs at a time. Completion rechecks file identity, routing and cancellation before playing. Pending clips show Wait. Failed normalization reports a local error and does not play the unnormalized original.

Cache under soundboard-cache/peak-v1 beside the config, keyed by absolute source path, size, modification time and normalization version. Publish completed output atomically from a uniquely named temporary file; incomplete outputs are removed. Reuse completed cache entries and prune obsolete generated entries from the known cache directory on catalogue scans, preserving active files until they can be removed. No work occurs when disabled; preview never creates normalized audio or plays. Cached WAVs use the same endpoint-bound player as MP3s.
