## Architecture
The tray parent owns the existing serialized audio worker for its entire lifetime. A separate controls child renders the existing TUI and sends typed actions over inherited anonymous pipes. Child stdio is reserved for JSON IPC; it opens CONIN$/CONOUT$ for the display after allocating its own console. Closing that console, Q, or Ctrl+C ends only the child. No listener ports, public pipe names, credentials, or second DLL connection are needed. Only one controls child is permitted at a time.

Export narrow worker and connected-view entry points from tui. The standalone tui command retains its existing worker lifetime. Child state starts from the parent's latest complete state; edit IDs start above its EditAck and use the session launch timestamp as a floor to avoid collisions with still-queued edits from a prior controls session. Each controls session receives a fresh channel, bounded latest-state delivery and cancellation. Slow/closed controls cannot block the worker. JSON encoding is synchronous against immutable published snapshots; no shared mutation is introduced. EOF detaches the controls, with no transport replay. Disconnected queued actions still undergo existing revision/persistence guards.

Use getlantern/systray for Windows notification-area integration (including Explorer restart restoration). Its Windows implementation uses Win32 calls without CGO; isolate it behind Windows files. Native console and named-event wrappers live in a Windows desktop integration package, extending the root native-code isolation rule to this necessary boundary. A per-user/session, normalized absolute profile path plus live/preview mode named event guards tray instances. A second launch signals Open controls and exits. This is separate from the unchanged live-writer lock, which continues preventing conflicting profiles from writing.

Use a GUI-subsystem build for flash-free default launch. Explicit CLI commands attach to their invoking console or allocate one when needed; redirected streams are preserved. The internal controls entry point never opens a worker. Startup failures get a native error dialog; runtime connection/config/ownership failures remain visible in tray status and controls. No automatic login startup, hidden persistence installation, new recording commands or extra routing controls in this iteration.

The parent owns cancellation, pipes and child process cleanup. On Quit cancel the worker, close IPC, give controls bounded time to exit, and kill only that owned controls child if needed. Worker cleanup is bounded externally; quitting must not issue mixer/recorder transport commands. The tray status reports Preview, Connecting/Disconnected, Live, or Attention; errors are inspected in controls. Existing fallback/pending row indicators remain intact. Q is labeled Close in attached controls.

## Validation
Tests cover command selection, default live/explicit preview, IPC state/action roundtrips, stalled/disconnected child isolation, close/reopen edit acknowledgements, cancellation, status and single-instance signaling. Run Go tests, vet, Windows GUI build, strict OpenSpec validation and isolated dry-run tray/controls smoke tests. Real audio continuity and Explorer restart are separate manual acceptance. Race checks depend on available CGO toolchain.

Guard the tray library readiness callback with a five-second deadline because its Windows API logs native registration errors rather than returning them. Wake the owning Win32 message loop on failed readiness and show a startup diagnostic; never leave an invisible workerless process. Record unexpected child exits in tray status; normal detach is not an error.

Confirm icon registration using Shell_NotifyIconGetRect after the tray callback, with a bounded retry while Explorer processes registration. Match only the current tray thread's SystrayClass window (library v1.2.2, icon ID 100). Report a visible startup error if no icon is registered, rather than leaving background routing inaccessible. Windows remains in control of overflow placement; do not force pinning or change user shell preferences. Preview smoke launches must remove the development tool's NO_COLOR environment override; deliberate user NO_COLOR remains supported.
