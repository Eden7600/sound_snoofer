## Design
Optional studio.asio_playback defaults false for compatibility; enable in embedded default, tracked voice profile and active bin/config.json. Existing WDM priorities stay unchanged. When enabled and unique companion/driver evidence confirms the configured ASIO interface, offer its driver name in Playback Device. Manual preference validation permits the configured ASIO pattern. Installed driver alone never counts as present.
Select configured WDM output normally, then ASIO as fallback only if no eligible WDM candidate; explicit ASIO preference overrides priority while connected. Reuse reserved A1, without opening Volt WDM on another output or creating duplicate A1 operations. WDM playback still uses lowest free output excluding ASIO A1. Include configured ASIO A1 among managed playback migration buses to move sends both directions, but never clear A1 while the interface is connected. Source Off retains playback and A1. On disconnect retain preference and use WDM fallback; reconnect restores manual priority. Reject ambiguous hardware using existing rules.
Update the audio invariant: playback normally uses the lowest free output, except selecting the ASIO interface itself reuses its reserved A1. Preserve unrelated outputs and recorder/monitor routing following logical playback. Existing saved manual preferences remain untouched. User reload/restart applies config; no live writes during development.
## Validation
Cover automatic priority, explicit override, presence/ambiguity, disconnect/reconnect, bidirectional send migration and mic Off. Full tests, vet, Windows replacement build, strict validation, isolated picker preview. Listening/hotplug acceptance remains unperformed.
